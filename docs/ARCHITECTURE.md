# 后端架构与接口边界

当前实现为单用户模块化单体：API、CLI 调用相同业务服务，单独 Worker 执行数据库任务。
资料、会话和账号数据不对外部署；Compose 宿主端口绑定本机。

## 数据流

1. 导入提交 `jobs`，Worker 保存原始内容哈希、快照和文字块。
2. 显式提取任务把文字块交给所选模型，校验后保存候选记忆和证据；不会自动确认。
3. 用户确认后建立 FTS5 索引。纠正新增版本并撤销原确认；停用、删除同步影响检索。
4. 会话按 owner、account、platform、peer、thread、scope 隔离。公开上下文只使用公开确认记忆，
   且全部来源必须公开；SQL 过滤先于结果限额和证据组装。
5. 模型只收到合格证据和当前会话的提问历史；旧草稿、会话摘要不作为事实来源。
6. 生成后在 SQLite 写锁内复核证据并保存草稿。没有发布工具；`actions` 只保存草稿与策略信息。

## 主要模块

| 模块 | 职责 |
|---|---|
| `storage` / `content_models` | 原始来源、内容块、候选与版本化记忆、检索 |
| `models_gateway` | DeepSeek / GLM HTTP 边界与显式模拟提供商 |
| `bilibili` | 固定版本 CLI、允许的操作、参数校验、脱敏与错误归一化 |
| `services` | 会话、模型调用元数据、证据上下文和草稿 |
| `jobs` / `worker` | 租约、有限重试、任务恢复和风控暂停 |
| `api` / `cli` | 本机管理入口，不直接执行社交发布 |

`LLMGateway`、`PlatformAdapter`、`Retrieval` 协议定义在 `contracts.py`。
没有引入 Agent 框架，模型不获得 Shell、任意 CLI 或修改自身策略的权限。

## 持久化与恢复

数据库当前迁移版本为 `0002_proposal_identity`。首版包括原始资料、媒体预留、记忆、证据、
版本、身份与账号、会话、消息与摘要、任务、草稿、模型调用、审计和暂停配置。
不声称复原原聊天附件的 21 张表。

任务在认领时原子更新租约 token；完成时校验 token，过期 Worker 不能覆盖新结果。
抽取提议使用原始事实与证据的确定性标识，恢复重跑不覆盖用户纠正或重复建同一条记忆。
这属于精确提议去重，不是语义去重；云端调用本身仍可能在重试时再次计费。

备份使用 SQLite 在线备份并保持写锁，记录引用原文件的路径映射与哈希；恢复校验 ZIP
路径、大小、SQLite 完整性、外键和原文件 SHA-256，重定位到新目录。凭证与 `.env` 不包含在备份中。

## 实际能力与已知限制

- 文本、Markdown、规范 JSON 可导入。多模态只有数据结构，尚无 OCR、ASR 或视觉提取器。
- 检索为关键词及三元字符匹配，暂不具备语义向量检索；证据引用不能证明模型陈述语义完全正确。
- 元数据调用统计包含模拟标识和 token，不估算金额；不保存完整 Prompt 或 Cookie。
- B站搜索、详情和评论已有匿名实测，登录及字幕仍需要账号联调；不会后台持续轮询。
- 备份不包含账号登录材料；删除的记忆若从仍保留的原始资料再次显式提取，可重新成为候选，
  但不会自动确认。崩溃可能留下未引用原始文件，尚无自动清理任务。
- 历史草稿属于私有管理记录，可查看，但不会重新作为公开问答证据。外部事件 ID 对应内容不可变。
- 同一事件的并发生成最终仅保存一份草稿，但并发模型请求可能各消耗一次用量。

## 后续前端接入

使用 `docs/openapi.json` 生成客户端类型，或者直接访问本机 `/openapi.json`。
普通查询使用 REST，任务通过 `/api/v1/jobs/{id}` 轮询。管理请求携带 Bearer Token；
前端不接触数据库、B站凭证或模型 Key。业务页面和 SSE 均留到后续。
